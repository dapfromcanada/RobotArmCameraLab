# Bench findings 2026-10-21 (Derek + camera_lab)

Cameras: Lucid Triton TRI054S-C (233100505), JAI AP-3200T-PGE (U330439). Charts: Letter
step wedge, grey patch, resolution, tag card. Raw tables: the other files in this folder.

## User sets
- **JAI:** `UserSetSave` is refused while acquiring ("Node is not writable") and works with
  the stream stopped. Proven: save → change exposure/WB → `UserSetLoad` → saved values back.
  User Set 1 now holds the setup values (14 959 µs, 0 dB, WB R 0.973 / B 1.176). The JAI has
  no `UserSetDefault`: whether it **boots** from User Set 1 needs a power-cycle test.
- **TRI054S:** save to User Set 1 + `UserSetDefault = UserSet1` worked. Its user sets do NOT
  store `HDRTuningEnable` or the HDR channel exposures/gains, so HDR on/off and the channel
  values are not restored by a power cycle.

## Brightness and noise
- Exposure × gain is linear on both cameras (constant output across the sweeps).
- Exposure longer than one frame lowers the frame rate (TRI054S: 61 ms → 16 fps,
  122 ms → 8 fps, 244 ms → 4 fps).
- **Spatial σ on a printed patch is not camera noise.** It measures print texture and the
  light gradient (it did not change with gain or with frame averaging). Use **temporal
  noise** (two frames differenced, /√2) for gain limits.
- Temporal SNR at equal brightness (12-bit, centre crop, median of 3 frame pairs):

  | gain dB | 0 | 6 | 12 | 18 | 24 | 30 | 36 | 42 |
  |---|---|---|---|---|---|---|---|---|
  | TRI054S SNR (level 0.115) | 142 | 93 | 74 | **108** | 86 | 76 | 67 | 52 |
  | JAI SNR (level 0.178) | 50 | 36 | 25 | 18 | | | | |

  JAI: ×1.4 SNR loss per +6 dB (shot-noise rule). TRI054S: 18 dB is quieter than 12 dB,
  consistent with a sensor gain-mode switch (e.g. dual conversion gain) — verify in the
  fingerprint before relying on it.
- **Frame averaging works:** 4 frames halved the temporal noise on both cameras (√4).
- No light flicker in the bench light (frame-to-frame brightness change 0.01–0.04 %,
  no rolling-shutter banding).
- 8-bit hides the TRI054S's noise floor (σ below one 8-bit step at low gain): fingerprints
  must use 12-bit formats.

## HDR (TRI054S, gains fixed 19.8 / 4.2 / 29.4 / 4.2 dB)
- Wedge white vs channel exposure: 5 ms 0.34, 10 ms 0.48, 20 ms 0.68, 30 ms 0.83,
  40 ms 0.96, 47.9 ms 1.00 (clipped). Doubling exposure gives ×1.4: tone-compressed output.
- The printed step wedge resolves ~15 steps with HDR on or off: the print's own range is
  too small to show HDR's benefit. That needs a high-dynamic-range scene (bright highlights
  and dark shadows in one view).

## Setup procedure fixes from today
- JAI save pauses the stream; save failures are recorded with the camera's exact answer.
- The setup now enters the profile's mode first (the TRI054S setup had used HDR knobs while
  the camera was in HDR-off).
- TRI054S HDR: channel exposure capped at one frame (47.9 ms), gains fixed (profile).
- TRI054S explicit frame-rate changes pause the stream (the GUI slider was refused).

## Power-cycle test (Derek, 2026-10-21, read raw without camera_lab configuring)
- **JAI:** boots from User Set 1 (UserSetSelector = UserSet1; exposure 14 959 µs, AnalogAll ×1,
  AnalogRed 0.97266, AnalogBlue 1.17578, autos off, RGB8, 12.03 fps) — even without a
  UserSetDefault feature. (The JAI reports no uptime, so the reboot itself is per Derek.)
- **TRI054S:** DeviceUpTime 42 s (rebooted); loaded its boot set UserSet1: exposure
  29 991 µs, gain 28.6 dB, WB R 1.898 / G 1.005 / B 1.675, autos off, BayerRG8, free-run.
  **HDRTuningEnable = False after boot** (not stored in user sets). HDR channel gains read
  19.8 / 4.2 / 29.4 / 4.2 dB — the same values found this morning, most likely the firmware
  defaults; channel exposures came up equal to ExposureTime (29 991 µs).
  → For HDR use, the application must enable HDR and set the channels after power-up.
